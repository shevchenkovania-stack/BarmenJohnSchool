# 7. То, о чём никто не спросил: дополнительные риски

> Роль: техлид. Ниже — вопросы, которых не было в брифе, но которые
> решают судьбу первого релиза: доступность, данные, закон, магазин,
> деньги, поддержка, мёртвый код.

## 7.1. Данные и приватность

| Риск | Факт | Что делать |
|---|---|---|
| Прогресс не переносится | SharedPreferences + Hive локально, без бэкапа | перед релизом: экспорт/импорт прогресса в файл (JSON) — дешевле аккаунтов |
| Имя ученика в дипломе | сохраняется в SharedPreferences открытым текстом | это не ПДн критичного уровня, но в политике конфиденциальности указать |
| Ключ OpenAI в secure storage | хранится на устройстве | при выключении AI (см. файл 6) убрать экран; при включении — политика |
| Удаление данных | нет кнопки «удалить всё» в настройках | добавить «Сбросить прогресс» с подтверждением — магазин этого ждёт |
| Аналитика | нет `firebase_analytics`/crashlytics — падения не видим | для v1 минимум: `Firebase Crashlytics` или локальный лог-файл, который пользователь может отправить |

## 7.2. Закон и магазин (Alcohol / 18+)

1. **Play Console: Content rating.** Вопросник про алкоголь → рейтинг
   18+ (или «высокая зрелость»). Без этого релиз отклонят.
2. **Политика конфиденциальности обязательна** (приложение доступно
   детям по store listing, но контент 18+). Нужен URL.
3. **Data safety** — заполнить честно: «данные не передаются» (если AI
   выключен).
4. **Описание магазина** не должно обещать «сертификат бармена» как
   официальную квалификацию. Формулировка: «учебный курс, не является
   профессиональной сертификацией». Иначе — жалобы и проверки.
5. **`android:label` = «Бармен Джон»**, а на экране «Школа бармена
   Джона» — расхождение. Привести к одному.

## 7.3. Доступность (Accessibility)

Сейчас почти не проверено:

- [ ] TalkBack: читаются ли кнопки-иконки (нет `semanticLabel` у
      `Image.asset`), понятны ли квизы?
- [ ] Контраст: см. файл 1, п. 1.8.
- [ ] Масштаб системного шрифта: `coffee_list_app.dart` форсирует
      `TextScaler.linear(settings.fontScale)` — это **перекрывает**
      системную настройку пользователя. Нужно перемножать, а не
      заменять (или хотя бы предложить «системный» вариант).
- [ ] Минимальный размер кнопки 48×48: часть кнопок (иконка настроек
      10+20 padding) меньше.
- [ ] Анимации: `MediaQuery.disableAnimations` не учитывается.

## 7.4. Производительность и размер

- APK/AAB: 90+ MB (упоминается в MASTER_PLAN). Многое даёт
  `google_mlkit_translation` и `printing/pdf`. При выключении AI/перевода
  размер упадёт.
- Первый запуск: 20+ `print`-логов в `main`, загрузка JSON на старте —
  проверить холодный старт < 2 с.
- `print` в коде: 260 вызовов. В release они остаются в консоли (не
  страшно, но 260 строк лога — шум и потенциальная утечка путей).
  Заменить на `kDebugMode`.

## 7.5. Мёртвый код — риск для магазина и для правок

Экраны/сервисы, которые **есть в проекте, но недоступны** из навигации
v1 (проверено по ссылкам):

```
bar_manager/ (5 экранов), menu_builder, guest_mode (+kiosk), qr_menu,
cost_calculator/price_book, favorites, search, ai_recipes,
cocktail_builder (3 экрана + viewmodel), cocktail_list,
coffee_list, coffee_single, repozitories/ (старый слой),
daily_quests_screen, bartender_shelf_screen
```

Два последствия:
1. **Пользователь до них не дойдёт, но они компилируются и могут
   ломать сборку/анализ** (сейчас 212 info-замечаний).
2. Их можно случайно включить «одной строкой» в спешке и выпустить
   недоделанную фичу.

**Решение для v1:** удалить или вынести в `lib/legacy/` с явным
комментарием. Это самая дешёвая работа с самым большим эффектом на
стабильность.

## 7.6. Поддержка и обратная связь

- Нет экрана «О приложении»: версия, лицензии, контакт.
- Нет кнопки «Сообщить о проблеме» (хотя бы `mailto:` через
  `url_launcher`, который уже в зависимостях).
- Нет объяснения, куда писать, если диплом не выдался.

**Минимум v1:** экран «О приложении» → версия, ссылка на политику, e-mail,
кнопка «Сбросить прогресс».

## 7.7. Монетизация (даже если «бесплатно»)

Сейчас в коде есть валюта (монеты), уровни практики, значки — это
игровая экономика без цели. Решить до релиза:

- **Вариант 1:** убрать валюту полностью (проще всего, ничего не
  сломается в обучении).
- **Вариант 2:** оставить как «опыт» и убрать цены у мудрости.
- **Вариант 3:** заложить под IAP позже (не делать в v1).

Рекомендация: вариант 1 или 2. Валюта без трат — балласт, а с тратами
(мудрость) она создаёт «paywall» в бесплатном учебном продукте.

## 7.8. Юридические формулировки в тексте

Убрать/заменить:
- «Сертификат» → «Диплом об окончании курса (учебный)».
- «Certificate of Bartending Apprenticeship» — не выдуманное ли
  официальное звание? Добавить дисклеймер.
- Не писать «International», «Professional» без сертификации.

## 7.9. Технический долг, который ударит после релиза

| Долг | Почему важно |
|---|---|
| 17 слайдов мудрости рендерятся как `theory` (файл 4) | после релиза это нельзя «тихо починить» без потери отзывов |
| `passingScore` пустой у половины квизов | нечестная проверка |
| `orElse: theory` без лога | любые новые типы слайдов будут молча ломаться |
| `serif` вместо конкретной семьи | типографика плывёт на разных телефонах |
| 260 `print` | шум, утечка путей, нет диагностики у пользователя |
| `com.example.coin` | блокер магазина (см. TODO_RELEASE_PLAN) |
| release подписан debug-ключом | блокер магазина |
