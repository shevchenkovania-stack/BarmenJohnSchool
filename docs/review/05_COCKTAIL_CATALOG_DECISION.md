# 5. Решение: что делать с каталогом коктейлей

> Роль: продакт. Вопрос из брифа: «в приложении есть куча коктейлей —
> могут открываться по мере прохождения, или сразу, или вообще не нужны?»

## 5.1. Факты (проверено по коду)

| Что | Факт |
|---|---|
| Источник «кучи» | TheCocktailDB через `CocktailRepository` (поиск по буквам, случайный, фильтры) |
| Объём | внешняя база ≈ 400–600 коктейлей |
| Кэш | Hive (`CocktailCacheService`) — но заполняется **только когда есть сеть** |
| Где показывается | `CocktailListScreen` — «Рецептурный архив» |
| Подключён к навигации? | **Нет.** Ни `MainShell`, ни `HomeScreen`, ни `school_home` его не открывают |
| Открытие («unlock») | `CocktailListViewModel.isCocktailUnlocked`: практика > 0★ или урок с `diplomaCocktailId`; **не-учебные коктейли открыты всегда** |
| Секции списка | «Мой путь», «Классика Level 1», «По технике», «Все» |
| В виртуальном режиме | `VirginCocktailService` синтезирует безалкогольные версии |

Итог: **логика «открытия по мере прохождения» уже написана, но
пользователь до неё не может дойти**, потому что экрана нет в навигации.
При этом всё, что в коде уже открыто «всегда» для не-учебных коктейлей,
делает замки бессмысленными.

## 5.2. Три варианта, и что каждый означает

### Вариант A: «Все рецепты сразу» (справочник)
- Все коктейли доступны, поиск и фильтры.
- **Плюс:** полезно сразу, привычно, легко объяснить.
- **Минус:** конфликтует с продуктом «школа»: зачем учиться, если всё
  под рукой? И требует честной работы офлайн (сейчас без сети пусто).

### Вариант B: «Открывается по мере обучения» (коллекция)
- Открывается то, что прошёл: урок → коктейль; практика → коктейль.
- **Плюс:** усиливает мотивацию, согласуется с дипломом и звёздами,
  создаёт «коллекцию».
- **Минус:** до 100 % готов только после всего курса; нужно мало рецептов,
  иначе пустые экраны; требует офлайн-данных.

### Вариант C: «Не нужны в v1»
- Убрать из сборки. Школа = уроки + практика + мудрость + диплом.
- **Плюс:** самый быстрый и честный релиз, никакой пустоты и «426
  коктейлей из интернета».
- **Минус:** вы теряете USP «справочник» и придётся объяснять в
  описании, что рецептов нет.

## 5.3. Рекомендация: B-lite (гибрид, готов к v1 за 1–2 дня работы)

**Для v1:**

1. **Вшить в приложение небольшой курируемый набор — 24 коктейля**
   (Level 1 + Level 2 практики: Margarita, Whiskey Sour, Tom Collins,
   Cosmopolitan, Old Fashioned, Last Word, Penicillin, Mojito, Daiquiri,
   Negroni, Boulevardier, Pisco Sour, Mai Tai + Level 2) **своими**
   данными: название, состав в мл, метод, бокал, garnish, 2–3 совета
   Джона. Никакого API.
2. **Открытие по прогрессу:**
   - коктейль урока C открывается после урока C (теория + квиз);
   - остальные практики — после 2★ в Мастерской;
   - не связанные с программой — не включать в v1 вообще.
3. **Экран** = «Рецепты» (часть школы, комната Recipe Archive):
   - 3 вкладки: «Мои» (открытые), «Классика» (все 24, замки),
     «Техника» (shake / stir / build);
   - замок = «Откроется в уроке 10», а не просто закрытая картинка.
4. **TheCocktailDB** оставить только как запасной источник и убрать из
   пользовательского пути в v1 (или за флагом функции). В офлайне он
   даёт пустой экран — это похуже, чем отсутствие фичи.

**Почему не «все сразу»:** продукт продаётся как школа. Открытие по
урокам — это ровно то, что отличает его от 30 бесплатных приложений
с рецептами. И это уже почти написано в коде.

## 5.4. Что это даёт продукту

| Эффект | Оценка |
|---|---|
| Убирает пустой экран без сети | обязательно для offline-first |
| Убирает «426 незнакомых коктейлей» | фокус на 24 изученных |
| Создаёт причину пройти урок | мотивация |
| Создаёт ощущение коллекции | возвращаемость |
| Работает без лицензионных вопросов TheCocktailDB в v1 | безопасно |

## 5.5. Что нужно решить заранее (вопросы к владельцу)

1. **Тексты рецептов** — сами напишем (RU/EN) или оставляем
   англоязычные названия? Рекомендация: русский текст, латинские
   названия.
2. **Офлайн** — куда кладём данные: `data/content/cocktails.json`
   (как уроки) — рекомендую.
3. **Вирджин-версии** (`VirginCocktailService`) — в v1 не нужны, если
   нет раздела; иначе включать как «Безалкогольный вариант» в карточке.
4. **Избранное/поиск** — не в v1.

## Что выкинуть

1. Список «Все 426 коктейлей» из пользовательского пути v1.
2. `CocktailBuilderScreen`, `MenuBuilderScreen`, `BarManagerScreen`,
   `QR/Guest mode`, `PriceBook`, `Inventory`, `StopList`, `CanMake`,
   `CustomRecipes`, `Favorites`, `Search` — не подключены и не нужны
   первому релизу (см. файл 7).
3. Вирджин-генератор из v1.

## Критерий «готово»

- [ ] Рецепты доступны в авиарежиме.
- [ ] Каждый рецепт связан с уроком или практикой.
- [ ] Замок объясняет, где открыть.
- [ ] Ни одного экрана, который без сети пуст.
