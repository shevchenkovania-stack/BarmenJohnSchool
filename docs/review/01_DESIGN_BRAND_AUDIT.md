# 1. Дизайн, арт и бренд: аудит по экранам

> Роль ревьюера: арт-директор / бренд-ревьюер. Собран по коду: размеры
> шрифтов, семьи, цвета, отступы, ассеты. Оценка — по критерию «можно ли
> это выпускать как цельный продукт».

## 1.1. Бренд: сейчас это четыре разных продукта

| Где | Название | Проблема |
|---|---|---|
| `home_screen`: «ШКОЛА БАРМЕНА ДЖОНА» | зовём «Школа» | ок |
| `android:label` = «Бармен Джон» | магазин | расходится с экраном |
| Ассеты `barista_john_*.png` (7 файлов) | «бариста» | бариста — не бармен; латте-арт в дипломе о коктейлях |
| Диплом: вотермарка `JR`, `certificates_screen` | «JR» | наследие старого названия «JR Коктейль», осталось от прототипа |
| `cocktail_list_screen`: «Рецептурный архив» | пятое имя | не связано с «школой» |

**Вердикт P0.** Для релиза нужно одно имя и один список сущностей:
«Школа бармена Джона» → «Атлас» или «Рецепты» (внутри школы) → диплом
«Diploma of Bartending». `JR` в дипломе убрать: вотермарка чужого
бренда на сертификате выглядит как подделка.

## 1.2. Типографика: `fontSize` — 20 разных значений

По фактическому коду экранов школы собраны **все** использованные размеры:

```
certificates: 7, 8, 10, 11, 12, 13, 14, 15, 18, 20, 22, 24, 120
lesson:       8, 10, 11, 12, 13, 14, 15, 16, 18, 19, 20, 22, 24, 25, 28, 36, 40, 46, 48, 80
quiz:         12, 13, 14, 15, 16, 18, 20, 24, 28, 36, 60, 80
practice:     9, 11, 12, 13, 14, 15, 16, 18, 22, 24, 32
workshop:     10, 11, 12, 14, 15
```

Проблемы:

1. **Нет типографической шкалы.** 13, 15, 16, 18, 19, 20, 22 — это не
   уровни, а «на глаз». Девятый и одиннадцатый кегли в одном экране
   (`practice_flow_screen`) читаются как случайность.
2. **8, 9, 10 px** — ниже предела читаемости на телефоне (рекомендация
   минимум 11–12 для вспомогательного текста, 14 — для основного).
3. **Одна и та же роль выглядит по-разному**: заголовок экрана — 19 на
   главной, 20 в `JohnThemedAppBar`, 18 в `term_quiz`, 20 в `quiz`.
4. **`serif` как family-строка** — не конкретный шрифт. Где-то текст
   получает Georgia, где-то системный serif, где-то (если Google Fonts не
   загрузился) — Roboto без засечек. Один и тот же экран выглядит
   по-разному на разных устройствах.
5. **Смешение двух наборов**: `GoogleFonts.cinzel/ebGaramond/cormorantGaramond`
   в дипломах и брифингах, `fontFamily: 'serif'` во всех остальных
   экранах школы.

**Вердикт P0.** Ввести шкалу из 6 шагов и заменить все `fontSize`:

| Токен | Размер | Применение |
|---|---|---|
| `display` | 28–32 | экран-победа, диплом |
| `h1` | 22 | заголовок экрана (AppBar) |
| `h2` | 18 | заголовок карточки/слайда |
| `body` | 15–16 | основной текст (никогда меньше 14) |
| `small` | 13 | подписи, метаданные |
| `micro` | 11 | только служебное, не для чтения |

Плюс зашить статические `.ttf` (см. файл 7, п. «шрифты») и использовать
две семьи: заголовки и тело. Три грузовых Google-семьи в одном продукте —
лишний вес и лишний визуальный шум.

## 1.3. Цвет: палитра комнаты победила, но не везде

Уже сделано (2026-11-07): экзамен, результат, барный слайд и достижения
переведены на палитру комнаты, `ColorScheme` получил явные
`secondary/tertiary`.

Осталось:

| Место | Проблема | Приоритет |
|---|---|---|
| `main_shell` снекбар | `Color(0xFF252336)` — фиолетовый из старой темы | P1 |
| `app_theme` `textSecondary #B0ABCF` | холодный лиловый текст вне школы (настройки, словарь) | P1 |
| `certificates_screen` | своя тема `_DiplomaTheme.of(level)` — третий набор цветов | P1 |
| Эмодзи как иконки | ⭐🪙🏆💪📚🌿🍸🍋 в 20+ местах | P1 |

**Про эмодзи (P1, но важный).** Эмодзи рендерит система: на Xiaomi — жёлтые
«Noto», на Samsung — другие, на старых Android — чёрно-белые квадратики.
Для «премиального» бара это главный визуальный дефект. У школы уже есть
свой набор `ui_icon_*.png` — надо добить его до полного набора
(награда, монета, кубок, звезда, замок) и убрать эмодзи из UI.

## 1.4. Композиция и отступы

| Экран | Наблюдение | Вердикт |
|---|---|---|
| Главная | шапка 70 px аватар + шестерёнка, 1 карточка уровня, 2 быстрых действия — много воздуха, мало смысла | P1: добавить прогресс уровня и «продолжить урок» |
| Level 1 | сетка карточек — единственный экран с хорошей плотностью | ок |
| Урок | панель + карточка Джона + текст: три вложенных «дерева» с разными радиусами (18/16/12) | P1: один радиус (16) |
| Квиз | крупный прогресс-бар, панель, варианты 2 px рамка — читается | ок |
| Практика | 5 разных подложек, кнопки с `height: 50` вручную | P1: единые кнопки |
| Мастерская | «блок A/B/C» + карточки-коктейли | P0: непонятная структура (см. файл 4) |
| Диплом | самый сложный экран: рамка-градиент, орнаменты, вотермарка, 3 семьи шрифтов | P1: упростить до одного листа |

**Отступы.** Сейчас `EdgeInsets.all(20)`, `all(24)`, `all(16)`, `fromLTRB(16,16,16,24)`
и `symmetric(horizontal: 16, vertical: 24)` вперемешку. Нужна сетка 4/8:
экранные поля 16, между блоками 16, внутри карточки 12–16. На текущий
момент разница в 4–8 px создаёт «дрожание» при переходах между экранами.

## 1.5. Кнопки

| Кнопка | Где | Проблема |
|---|---|---|
| «Далее» / «К тесту» | урок | `OutlinedButton` для «Назад» и `ElevatedButton` для «Далее» — ок; но на первом слайде «Далее» растянута `flex: 2` и выглядит как главный CTA экрана (им не является) |
| «Проверить / Готово / Далее» | квиз | три разные подписи на одном месте; пользователь не понимает, что кнопка меняет смысл до ответа |
| «Проверить» (x4 в одном вопросе) | matching / sequence / multiple / slider | четыре разных «Проверить» — нужен один паттерн «Ответить» |
| «Завершить (3/7)» | тест терминов | число в скобках = правильные ответы, не очевидно |
| «Начать» | практика | ведёт к шагу «выбери ингредиенты», но подписи «Дальше» на следующих шагах |
| Кнопка результата | квиз | градиент + эмодзи внутри — единственная «неоновая» кнопка продукта |

**Вердикт P1.** Один стиль действий: `primary` (заполненная золотом),
`secondary` (обводка), `text`. Подписи — глагол действия: «Ответить»,
«Следующий вопрос», «Завершить экзамен». Запретить двум кнопкам с
одинаковым текстом стоять на одном экране.

## 1.6. Изображения и арт

- 7.5 MB в `images/` — уже хорошо после оптимизации.
- Карточки уроков — фото-коллажи в разном стиле (где-то коктейль на
  барной стойке, где-то предмет). Уровень «премиум» требует единой
  обработки: одинаковое освещение, одинаковый ракурс, единая палитра.
  Сравните `lesson_a_01_balance.jpg` и `lesson_f_23_service_rush.jpg` —
  они из разных вселенных.
- Джон: 7 разных поз (`barista_john_teach/practice/exam/celebrate/hero/logo`)
  в разной стилистике (где-то реалистично, где-то как логотип).
- **Нет ни одного скриншота для магазина** и нет Feature Graphic.

**Вердикт P1.** До релиза: 1 стиль для карточек (или хотя бы единая
цветокоррекция), 1 стиль для Джона, 4–8 скриншотов на телефон с
реальным прогрессом.

## 1.7. Движение

- Анимации есть точечно: трофей `elasticOut`, кубки `bounceOut`, шевеление
  при неверном ответе (400 мс).
- Нет системного ощущения: переходы между экранами стандартные Material.
- `SlideType.interactive` с анимацией отсутствует — интерактивы выглядят
  «статично» по сравнению с остальным.

**Вердикт P2**: единый переход, анимация появления карточки Джона,
уважение `MediaQuery.disableAnimations` (доступность, см. файл 7).

## 1.8. Тёмная тема и контраст

Приложение тёмное, но есть места с риском недостаточного контраста:

- `onDark.withAlpha(150)` на дереве → около 3.5:1, ниже WCAG AA (4.5:1)
  для основного текста;
- `fontSize: 9–10` (микро-подписи в практике) в сочетании с прозрачностью;
- белый текст `Colors.white` на золотом фоне (`quiz`, варианты) — ниже 3:1.

**P1**: проверить контраст по WCAG AA для всех текстов, микро-подписи
не использовать для смысловых данных.

## Что выкинуть до релиза

1. **Эмодзи как иконки** — заменить на `ui_icon_*` или убрать.
2. **`JR` в дипломе** — наследие прототипа.
3. **Три Google-семьи в дипломе** — оставить одну.
4. **`fontSize: 8/9/10`** — увеличить или убрать.
5. **Вторую тему цвета** (`textSecondary` холодный лиловый вне школы) —
   свести к одной палитре.

## Критерий «дизайн готов»

- [ ] Один набор названий продукта во всех текстах и в магазине.
- [ ] Шкала из 6 размеров, ни одного `fontSize` вне шкалы.
- [ ] Две статические семьи шрифтов, работают офлайн.
- [ ] Ноль эмодзи в UI (кроме, если нужно, реакции на ответ — и то
      лучше своей иконкой).
- [ ] Одна цветовая палитра для всех экранов, включая диплом.
- [ ] Кнопки: три стиля, никаких двух разных кнопок с одинаковым текстом
      на одном экране.
- [ ] 4–8 скриншотов, иконка, Feature Graphic.
