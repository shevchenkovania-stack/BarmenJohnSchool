# 03. Technical Roadmap

Как превратить существующий код в игру. Написано по факту; каждый шаг
проверяем. Порядок выбран так, чтобы **играбельный прототип** появился раньше,
чем «полная архитектура».

Читать вместе с:

- `docs/GAME_DESIGN_HANDOFF.md` — что есть сейчас;
- `01_GAME_DESIGN_DOCUMENT.md` — правила игры;
- `02_STORY_BIBLE.md` — содержание Главы I.

---

## 1. Принципы реализации

1. **Не дублировать то, что есть.** Пять из семи «движков» концепции уже
   реализованы (см. `00_REVIEW_OF_CONCEPT.md`, раздел 2.2).
2. **Один новый слой**, а не семь: `StoryEngine` над существующими сервисами.
3. **Сцена ссылается на проверку, а не описывает её.** Оценка остаётся в
   `PracticeChallenge` и `QuizScreen`.
4. **Офлайн обязателен.** Сценарии — ассеты, состояние — `SharedPreferences`.
5. **Идемпотентность сохраняется.** Награда выдаётся один раз.
6. **Данные — в JSON, логика — в Dart.** Контент меняется без пересборки
   логики, но не «всё в JSON»: проверки знаний остаются rule-based.

## 2. Целевая архитектура (минимальная)

```
lib/features/bartender_school/
├── data/
│   ├── story/
│   │   ├── story_scene.dart          модель сцены и её типов
│   │   ├── story_chapter.dart        глава = список сцен
│   │   ├── story_repository.dart     загрузка JSON из assets + парсинг
│   │   └── story_state.dart          состояние прохождения (prefs)
│   └── (существующее: progress_service, practice_challenges, guests, ...)
├── domain/
│   └── services/
│       └── story_engine.dart         переходы, условия, эффекты
└── presentation/
    └── screens/
```

Ничего из существующего не переписывается целиком. `StoryEngine` **вызывает**
уже готовые сервисы.

## 3. Модель сцены

### 3.1 Типы сцен

Только те, что опираются на существующие механики:

| Тип | Смысл | Реализуется через |
|---|---|---|
| `narration` | Джон говорит, 1–3 строки | `SlideType.theory/silence/quote` |
| `observation` | что видит бармен | `SlideType.observation` |
| `choice` | выбор хода в ситуации | `SlideType.choice` + эхо |
| `explain` | объяснение через предмет | `SlideType.toolVisual/failure` |
| `action` | собрать коктейль | `PracticeChallenge` |
| `check` | проверка знаний | `QuizScreen` |
| `reveal` | открытие: запись, коктейль, страница | `ProgressService` |
| `finish` | событие финиша эпизода | **новый экран** |

Тип `check` по умолчанию — **один** на главу. Два `check` подряд в одной главе
запрещены на уровне валидатора (см. 6.2).

### 3.2 JSON сцены

```json
{
  "id": "ch1_s04",
  "type": "choice",
  "room": "toolBench",
  "johnEmotion": "teach",
  "image": "images/lesson_b_07_shake.jpg",
  "title": "Какой из них встряхивали?",
  "lines": [
    "Один я встряхивал. Другой размешивал.",
    "Какой?"
  ],
  "audio": "glass_tap",
  "choices": [
    { "id": "c1", "text": "Прозрачный и гладкий", "correct": false,
      "reply": "Он гладкий потому, что его размешивали. Встряхивание даст воздух." },
    { "id": "c2", "text": "Матовый, холодный, с воздухом", "correct": true,
      "reply": "Вот он. Воздух — это след шейкера." }
  ],
  "remember": true,
  "next": "ch1_s05"
}
```

Правила схемы:

- `lines` — максимум 3 строки, каждая до 90 символов (валидатор);
- `audio` — только существующие файлы `assets/sounds/*`;
- `room` — только значения `JohnSchoolRoom`;
- `johnEmotion` и `image` — **обязательны**, оба указывают на существующий
  файл в `images/` (проверяется валидатором, раздел 11.6);
- `remember: true` — выбор уходит в `GuestEchoService`;
- `next` может отсутствовать у `finish`.

Новых ассетов сцена требовать не может. Если подходящей картинки нет — сцена
меняет тип (см. раздел 11.4).

### 3.3 Сцена действия

Сцена не описывает проверку — она на неё **ссылается**:

```json
{
  "id": "ch1_s06",
  "type": "action",
  "room": "workshop",
  "ref": "challenge_daiquiri",
  "onPass": "ch1_s07",
  "onFail": "ch1_s07",
  "replyOnFail": "Не страшно. Смотри, где ушёл баланс."
}
```

`onPass` и `onFail` ведут в **одну и ту же** сцену — так выполняется правило
«сюжет идёт вперёд всегда». Разница только в `replyOnFail` и награде.

## 4. StoryEngine (один класс, без фабрик)

Минимальный контракт:

```dart
StoryEngine
  Chapter chapter
  String currentSceneId

  StoryScene get current
  Future<void> advance(String? choiceId)      // переход + эффекты
  bool isUnlocked(String chapterId)
```

Эффекты описываются декларативно в сцене, применяются в одном месте:

| Эффект | Что вызывает |
|---|---|
| `awardRank` | `claimBlockReward` (есть) |
| `unlockCocktail` | `unlockedCocktails` (есть) |
| `revealWisdom` | `purchasedWisdom` / новый флаг открытия |
| `rememberChoice` | `GuestEchoService.remember` (есть) |
| `registerPractice` | `recordPracticeAttempt` (есть) |
| `finish` | событие финиша (новое) |

Оценка **никогда** не вычисляется в `StoryEngine`: он только вызывает готовые
сервисы и читает их ответ.

## 5. Экран сцены

Тонкий виджет: рисует `StoryScene`, не знает логики переходов.

Требования:

- фон — `JohnRoomBackground` с `room` из сцены (уже есть);
- свет — три состояния (сцена / напряжение / событие): расширить
  существующий флаг `evening`;
- текст — крупно, максимум 3 строки, кнопка всегда внизу;
- переход между сценами — короткая анимация, без затемнения в чёрный
  (чёрный = «пасмурность»);
- звук — по `audio` из сцены через `BarSoundService`.

**Важно:** экран сцены не дублирует `LessonScreen`. Первый эпизод
собирается на новом экране; старый остаётся для Level 2/Мудрости, пока миграция
не завершена.

## 6. Этапы

Порядок отличается от концепции: сначала **существующие дефекты**, потом
эпизод, потом движок на данных. Так игрок получает улучшение уже на 2-м шаге.

**Ограничение по арту (действует на всех этапах):** новых изображений нет и
не планируется до проверки главы. Всё делается из 52 существующих файлов
`images/`. Каждая сцена обязана собираться из них — иначе глава не идёт
в работу. Полный перечень ресурсов и правила — раздел 11.

### Этап 0. Починить петлю (0.5–1 день)

Без нового кода, только исправления:

| # | Что | Файл |
|---|---|---|
| 0.1 | Бейджи проверять после урока и квиза, не только практики | `progress_service.dart:704`, `quiz_screen.dart` |
| 0.2 | Гейт терминов: не открывать повторно внутри одного прохода | `lesson_screen.dart:79-96` |
| 0.3 | Прогресс урока доводить до 100% на последнем слайде | `lesson_screen.dart:562` |
| 0.4 | Уведомление о разблокировке бейджа (требование проекта, не выполнено) | новый виджет |

**Проверка:** тест «за урок выдаётся бейдж, показывается ровно один раз».

### Этап 1. Событие «Эпизод пройден» (1–2 дня)

Новый экран финиша: что изменилось / что стало понятно / что дальше.
Подключается после квиза и после практики.

**Проверка:** сквозной тест — урок → квиз → финиш → возврат.

### Этап 2. StoryEngine + Глава I (5–7 дней)

| # | Работа |
|---|---|
| 2.1 | `story_scene.dart`, `story_chapter.dart`, `story_repository.dart` |
| 2.2 | `assets/story/chapter_01.json` по `02_STORY_BIBLE.md`, раздел 7 |
| 2.3 | `story_engine.dart` с эффектами из раздела 4 |
| 2.4 | `story_scene_screen.dart` |
| 2.5 | Включить `GuestEchoService` в сцены `choice` |
| 2.6 | Глава I играется от пролога до финиша |

**Проверка:** пройти главу на устройстве; пройти дважды и убедиться, что XP не
удвоился.

### Этап 3. Валидатор контента (1 день)

Тест, который падает, если глава нарушает правила:

- два `check` подряд;
- строка длиннее 90 символов;
- больше 3 строк в `lines`;
- `room` не из `JohnSchoolRoom`;
- `audio` не из существующих ассетов;
- `action.ref` не существует в `allPracticeChallenges`;
- `image` или `johnEmotion` отсутствует либо указывает на несуществующий файл;
- `next` ссылается на несуществующую сцену;
- у `finish` есть `next`;
- в тексте сцены встречается определение из `TermService` дословно
  (признак «учебника»).

**Проверка:** валидатор проходит на Главе I и падает на заведомо плохой главе.

### Этап 4. Свет и звук события (1–2 дня)

Три состояния света вместо одного `evening`; звук на финише; остановка
движения (пауза) перед событием.

**Проверка:** визуальная приёмка в трёх комнатах.

### Этап 5. Миграция Level 1 (по одной главе)

Перевод уроков блока A в сцены. Правило: **не переводить всё сразу**. Первая
глава — эталон, по нему остальные.

**Проверка:** после каждой главы — тесты уровня зелёные, контент сверен
(lesson ↔ quiz ↔ challenge ↔ artwork ↔ progress, требование `AGENTS.md`).

### Этап 6. Проверка на людях

1. 5 человек, не знакомых с проектом.
2. Проходят Главу I без подсказок.
3. Вопросы после: что было вчера; что не так с бокалом; чем Shake отличается
   от Stir; вернёшься ли.
4. Критерий успеха — `01_GAME_DESIGN_DOCUMENT.md`, раздел 10.

---

## 7. Что делать нельзя (технические запреты)

1. **Не переносить логику оценки в JSON.** Правильность ответа — только в Dart.
2. **Не вызывать `unlockAchievement` из UI напрямую.** Только через сервис и с
   проверкой идемпотентности.
3. **Не давать `StoryEngine` доступ к `SharedPreferences` напрямую** — только
   через сервисы, иначе состояние разъедется.
4. **Не удалять `LessonScreen`**, пока Level 2 и Мудрость не мигрированы.
5. **Не добавлять новые типы интерактива** (слайдеры/перетаскивание), если UI
   не собирает и не оценивает ответ (`AGENTS.md`).
6. **Не хранить секреты** в сценариях и ассетах.

## 9. Риски

| Риск | Признак | Что делать |
|---|---|---|
| Сценарий превращается в текст | строк в сцене больше 3, нет действия | валидатор этапа 3 |
| Движок растёт раньше контента | появляются фабрики и абстракции без глав | правило «одна глава — один экран» |
| Двойной XP | повторный проход даёт награду | тест идемпотентности в этапе 2.3 |
| Рассинхрон lesson ↔ story | одна механика в двух местах | миграция только по одной главе за раз |
| «Пасмурность» остаётся | всё ещё один тон | этап 4 обязателен до проверки на людях |
| Офлайн ломается | сценарии тянутся из сети | JSON только из `assets/` |

## 10. Первый шаг в работе

Начинать с **этапа 0**: он не требует решений по контенту, снимает три
реальных дефекта и сразу делает прохождение менее «затянутым». После него —
этап 1, где появляется финиш. Только потом — Глава I.

## 11. Ресурсы: работаем без нового арта

Новых изображений нет. Главу, которая требует новой картинки, **не берём
в работу** — иначе мы снова упрёмся в ожидание художника и глава не выйдет
никогда.

### 11.1 Что есть (52 файла в `images/`)

| Группа | Файлы | Как использовать в сценах |
|---|---|---|
| Комнаты, 7 | `john_room_*.jpg` | фон сцены по `room`; уже подключены через `JohnRoomBackground` |
| Джон, 7 состояний | `barista_john*.png` | эмоция в сцене: teach, practice, exam, celebrate, hero |
| Джон-вырез | `scene/john_cutout_base.png` | персонаж поверх комнаты, без фона |
| Карточки уроков, 24 | `lesson_*.jpg` | иллюстрация к сцене знания (Daiquiri, shake, лёд, Negroni…) |
| Иконки, 8 | `ui_icon_*.png` | маркеры смысла: теория, практика, чек-лист, баланс, награда |
| Атмосфера, 3 | `wisdom_chest.jpg`, `wisdom_map_parchment_v2.jpg`, `sketches/*` | открытие, финиш, ретроспектива |
| Прочее | `logo.png` | заставка |

### 11.2 Чего критически не хватает

- гостя за стойкой (есть только **эмодзи** в `guests.dart`);
- двух коктейлей рядом для сравнения (сцена «Верстак»);
- предмета: старый блокнот, шейкер крупным планом;
- кадра «закрывающийся бар» (сцена 1).

### 11.3 Как обходим без картинок

Четыре приёма, каждый — только на существующих файлах:

**1. Гость — карточка и реплика, а не портрет.**
В `guests.dart` уже есть `emoji` и `signaturePhrase`. Гость показывается как
**карточка в деревянной панели** (`JohnWoodPanel`, уже есть) с крупным эмодзи и
одной строкой. Портрет не нужен: в сцене важна фраза, а не лицо.

**2. Сравнение — двумя панелями, а не иллюстрацией.**
Сцена «Какой встряхивали?» описывается словами на двух сторонах. Вместо
одной картинки — две панели рядом: «Прозрачный и гладкий» / «Матовый, с
воздухом». Ничего не рисуем, разница видна.

**3. Комната + вырез Джона = сцена.**
Фон комнаты (`john_room_tool_bench.jpg`), поверх — `john_cutout_base.png`
в нужной эмоции. Механика уже есть (`JohnRoomBackground`,
`barista_john_*.png`). «Камера» ближе к стойке — через `Alignment`.

**4. Предмет — иконка в рамке, с подписью и звуком.**
Блокнот = `ui_icon_book_theory.png` в панели + строка из
`john_backstory.dart`. Открытие подкрепляется `BarSoundService`, а не
картинкой.

### 11.4 Правило эскалации

Если сцена **не собирается** из этих четырёх приёмов — она переписывается
в сцену другого типа (`narration`, `choice`, `action`), а не отправляется
в очередь на арт.

Исключение: сцены **финиша** и **ранга** могут использовать
`barista_john_celebrate.png` — это единственный «праздничный» кадр, и его
надо беречь только для этих двух случаев.

### 11.5 Что можно заказать художнику позже

Только после того, как Глава I пройдена и принята:

1. гость за стойкой (один универсальный, без лица);
2. старый блокнот крупным планом — для повторяющегося открытия;
3. два коктейля рядом — если приём «две панели» окажется слабым.

Не больше трёх. Заказ на «всё остальное» до проверки главы бессмыслен.

### 11.6 Валидатор

В тест этапа 3 добавить проверку: у каждой сцены `image`/`johnEmotion`
указывает на **существующий файл** в `images/`. Опечатка в имени ассета
превращает сцену в пустую панель — это должно ловиться тестом, а не глазами.
